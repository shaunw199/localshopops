Seller operations, with each shop in control

Operational tools for independently owned Etsy shops.

LocalShopOps helps Etsy sellers organize authorized order data, review and prepare listings, produce operational reports, and coordinate production and fulfillment—without sharing Etsy passwords.

See how authorization works Review data protections
Availability: LocalShopOps began as a tool for the developer's own shop and is currently used by a limited pilot group of independently owned Etsy sellers. Broader seller availability is pending Etsy Commercial Access approval. The isolated Commercial Review candidate has completed offline acceptance testing for authorization, consent, tenant isolation, data freshness, write confirmation, revocation, and deletion controls. Real Etsy API credentials and production write operations remain disabled until the production environment is configured and the required approval is received.

Current purpose

One workspace for seller-authorized operations

Functions are enabled only for the shop and permissions approved by the seller.

01

Order and sales review

Synchronize and organize authorized order and sales records for operational review and reporting.

02

Listing workflows

Review listings, create drafts, and prepare seller-initiated listing or inventory edits with fresh-state checks and explicit confirmation.

03

Production and fulfillment

Create seller-directed production instructions, supplier workbooks, and fulfillment task lists. Exports are not automatically disclosed to suppliers.

04

Operational reporting

Generate shop-specific CSV and Excel reports while preserving seller and shop boundaries.

05

Permissions and confirmation

Use role-based access and require an authorized seller action before Etsy write operations.

06

Auditability

Maintain shop-scoped job status and audit records to support review and troubleshooting.

Write-operation boundaries

Human-confirmed changes with conservative limits

The Commercial Review candidate applies the same organization, shop, policy, snapshot, and audit controls to every supported Etsy write workflow.

01

Preview before change

A seller-authorized user sees a field-level preview and must confirm before a listing or inventory change is submitted.

02

Single-shop batch only

A batch may modify listings in one authorized shop only. Cross-shop editing, copying, and migration are rejected.

03

One draft at a time

Publishing is limited to one live draft after a fresh Etsy read, a fee warning, and a separate second confirmation.

Not supported: batch or automatic publishing, scheduled writes, listing deletion, deactivation, renewal, or automatic renewal.

OAuth authorization

Each seller connects their own Etsy account

LocalShopOps connects to Etsy Open API v3 through Etsy's OAuth 2.0 Authorization Code flow with PKCE. It does not ask sellers to provide Etsy passwords.

1

Seller starts the connection

For the Commercial Access release, the seller must first accept the LocalShopOps Terms and Privacy Policy, then choose Connect Etsy.

2

Etsy collects consent

The seller signs in directly with Etsy and reviews the specific permissions requested for enabled features.

3

Access remains shop-scoped

LocalShopOps binds the authorization to that seller and shop. Other sellers cannot access it.

Minimum permissions

Only the access needed for enabled functions

The Commercial Access production scope set is limited to the functions below. A seller must re-authorize if an additional scope is later required.

OAuth scopePurpose
transactions_rRead the authorizing seller's purchase and sales records needed for order operations.
listings_rRead the authorizing seller's private, inactive, or expired listing data.
listings_wCreate or edit seller-authorized listing drafts when that feature is enabled.
shops_rRead necessary information about the Etsy shop connected by the seller.

Not requested for current functions: the listing-deletion scope and access to the buyer_email field.

Data boundaries

Seller and shop isolation is a core product rule

LocalShopOps is designed so one seller cannot see or operate on another seller's Etsy data.

  • OAuth credentials and connection records are separated by seller and shop.
  • Orders, listings, jobs, permissions, exports, and audit records remain shop-scoped.
  • No cross-seller search, copying, or multi-shop listing modification is provided.
  • Listing deletion, deactivation, renewal, and automatic renewal are not provided.
  • No cross-seller benchmarking, marketplace analytics, or competitive analysis is created from Etsy API data.
  • Etsy data is not sold, exchanged, used for advertising, or used to train AI models.
  • No Etsy page scraping and no collection of Etsy member passwords.
  • Sellers can revoke Etsy authorization and request deletion of associated LocalShopOps data.

Seller-directed exports

Production data is shared only for a seller's workflow

Supplier and fulfillment exports are generated only when an authorized user selects the destination and initiates the export.

  • Exports may include order, item, personalization, recipient, or destination information only when reasonably necessary for the seller-directed production or fulfillment task.
  • LocalShopOps does not automatically disclose Etsy member data to suppliers, other sellers, or unrelated third parties.
  • Buyer email access is not requested for current functions.
  • Each seller remains responsible for choosing and authorizing its production and fulfillment providers.

Commercial Access readiness

Limited pilot now; broader access only after Etsy approval

LocalShopOps is being prepared for Etsy's manual Commercial Access review and will not open broader seller access before approval.

01

Offline acceptance complete

The isolated candidate has passed the defined offline acceptance suite for authorization, data isolation, listing and inventory workflows, lifecycle controls, and the English reviewer interface.

02

Reviewer access

Etsy reviewers may request a controlled demo, test instructions, and an interface walkthrough through the monitored support address.

03

Compliance controls

Data freshness, caching, incident notification, supplier disclosure, revocation, deletion, and backup-expiry controls are implemented and verified in the isolated candidate. Production deployment remains a separate approval gate.
